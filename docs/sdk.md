# SDKs for application developers

The **CLI** is a standalone end-user controller (`buds`). It is not the SDK.
Use an SDK to build your own GUI, CLI or integration. All use the same Rust protocol implementation.

## Rust SDK (source)

Download `OpenBuds-rust-sdk-source.tar.gz`. It contains the matching committed
workspace, lockfile, library source, examples/tests and build instructions; not
compiler-specific prebuilt `.rlib` files. Application sources are retained to keep
workspace paths valid, but building or using the SDK does not require Java,
Compose or the Android SDK.

Rust 1.88+ and a native linker are required. Linux also needs `pkg-config` and
`libdbus-1-dev`. From the extracted workspace:

```sh
cargo build -p realme-buds -p realme-buds-ffi --release --locked
cargo doc -p realme-buds -p realme-buds-ffi --no-deps
```

In your own application's Cargo.toml, use local paths to the extracted SDK:

```toml
[dependencies]
openbuds = { package = "realme-buds-ffi", path = "../OpenBuds-rust-sdk/bindings/c" }
realme-buds = { path = "../OpenBuds-rust-sdk/crates/realme-buds" }
```

`openbuds::session` provides the registered model catalog and model-selected
session API. `realme_buds::devices::air7` provides the lower-level typed Air7
protocol. Native Windows/Linux transports are separate workspace crates.
The package name `realme-buds-ffi` is historical; its Rust library name is
`openbuds`, and it exposes both Rust and C entry points.

See [model registration and capabilities](sdk-models.md), library API
documentation generated by `cargo doc`, and [Air7 limitations](air7.md).
Dependencies may require network access on the first build; the source download
is not an offline vendor bundle.

## C-compatible SDK (prebuilt per platform)

Download `OpenBuds-<platform>-c-sdk.zip` (Windows) or `.tar.gz` (Linux/macOS).
No Rust compiler is required to consume these libraries.

- Windows x64: `openbuds.dll`, MSVC import library `openbuds.dll.lib`.
- Linux x64: `libopenbuds.so`.
- macOS ARM64: `libopenbuds.dylib`.
- All: `include/openbuds.h`, C API documentation, `smoke.c`, matching source and notices.

Use the C ABI from C/C++, or your language's FFI (such as Python ctypes,
C# P/Invoke or Swift). Match the library architecture to your application.
The versioned ABI defines ownership, callbacks, threading and errors; no Rust
types cross that boundary. `smoke.c` exercises a synthetic transport without
touching earbuds.

Linux example (from the extracted C SDK):

```sh
cc smoke.c -Iinclude -L. -lopenbuds -Wl,-rpath,'$ORIGIN' -o sdk-smoke
./sdk-smoke
```

Windows Developer Command Prompt:

```bat
cl /Iinclude smoke.c openbuds.dll.lib /Fe:sdk-smoke.exe
sdk-smoke.exe
```

See `C-SDK.md` in the binary download, or [C API documentation](../bindings/c/README.md).

## Compatibility and licensing

Only realme Buds Air7 is implemented. macOS currently has **no built-in Bluetooth
transport**: a prebuilt library or GUI is not a claim of macOS device support.
The C API supports caller-supplied stream callbacks for embedding applications.
All SDKs are GPL-3.0-or-later, not permissive SDKs; preserve the license and
corresponding-source obligations when distributing applications.
